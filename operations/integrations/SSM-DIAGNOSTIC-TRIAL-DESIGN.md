## Evidence-first sequence; no execution in this task

1. Validate original policy snapshots against authorized current readbacks, lock versions/toolchain, AMI, saved plan, complete create/read/delete permissions and a source-hashed collector. Do not create a host while a known missing access/tool prevents collection or retirement.
2. Before SendCommand, immutable cloud-init installs a **bounded evidence exporter** only, not a new agent/framework. Capture sanitized STS/profile/AMI/agent version/service/channel state and document-fetch/authorization errors to the private exact log group. Preserve raw agent logs on encrypted disk until export review. Structured exported fields are allowlisted error/action/resource/request/command IDs and hashes, no tokens, authorization headers, credentials, app data or arbitrary command bodies. If safe export cannot be demonstrated locally, this prerequisite is not met.
3. Verify export arrival with normal read-only logs APIs first. A fixed bounded boot collector must continue long enough to capture the single command result even if Run Command never runs; it cannot depend on a later successful command to fetch its own failure logs. Stop/export/retire within the budget; never retain EC2 waiting on indefinite diagnosis.
4. Proposed single command is the owned, hash-pinned custom document with **Action=status only**, under the same operator. Preserve b2's Python status source in a minimal private read-only status harness/config; it reports absent/inert service state and performs no backup, timer start or event publish. Any narrowed Action schema/new document/hash/harness is an explicit part of this new trial proposal, not silent substitution or a claim of exact historical reproduction. Its compatibility with AMI Python and the complete source/hash must pass locally before admission. Do not send AWS-RunShellScript or an arbitrary shell command.
5. Capture raw sanitized SendCommand response, full ListCommands/ListCommandInvocations/GetCommandInvocation metadata, document/role/boundary hashes, CloudTrail correlation and exporter log evidence. On AccessDenied/unknown **do not retry or modify policy blindly**. Reaching the script proves only that new diagnostic execution, not b2 fixed or backup E2E.
6. Only new relevant evidence plus a separately reviewed specific correction could justify another command. No B→admin fallback, condition removal, same-approval reset or reuse of discarded resources. ## Owner idea: Session Manager from console

A Session Manager session is a **different capability** from Run Command. A successful session would help inspect/export agent logs but cannot prove SendCommand target authorization or be used to execute `observer_host.py status`/the rejected operation through another route. There is no host now and no session is opened here.

Recommend leaving sessions OFF in the minimum14-resource trial. If console inspection is later proposed, group it explicitly: StartSession on exact instance/custom session document; channel access; TerminateSession only the captured own session ARN; region-wide Describe/List metadata if the console requires it. Same approved operator, no switch to admin after refusal. A normal session may provide ssm-user/sudo/root administrative OS access, even if the intended commands are read-only; IAM does not make an interactive shell read-only. Disclose that risk and establish approved command/data/log limits, session expiry and private audit destination before opening. Do not modify account-wide session preferences, copy instance credentials, buy support or treat the user's suggestion as approval for new access. A session or policy denial is another observation, never a reason to swap principal/document. Additional permissions, session logging/storage and native close verification require their own exact reviewed delta before any action.
