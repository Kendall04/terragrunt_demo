## Concrete implementation

`collector.py` samples only the two documented SSM agent log paths, fixed systemctl fields, agent version and STS node-role/instance identity. It exports codes/actions from closed enums, UUID correlation IDs and line hashes; never raw lines, stderr, environment, credentials, arbitrary command bodies or file contents. Unknown error strings are omitted, so an empty summary is not proof of no error. Reads are bounded to64KiB/file,128 trailing lines,32 matching rows/file. Before PutLogEvents the record is structurally revalidated. At most120 samples and2MiB are published, no retry after failure or uncertain response. Partial CloudWatch rejection is failure. Existing CLI/agent/Python only; no installations or agent logging changes/restart.

The collector starts independently at cloud-init using one transient systemd service with a7500s runtime ceiling. It does not depend on the later SSM command. It checks its own source hash and exact node role/instance. Its default local CLI prints DESIGN_ONLY and never invokes AWS. A failed exporter prevents the command admission; logs are not recovered by secretly using another command or administrator.

`harness.py --action status` calls the existing `observer_host.control('status')` and exact dependencies selected by AST. Tests compare original function ASTs, including systemctl/uncertainty/config validation. Only BASE/STATE move to the isolated diagnostic directory; source hashes bind full original and subset. No checker, observer units, SDK, synthetic backup, SQS publisher or actual backup is installed. Unused fake backup/key metadata merely satisfies the unchanged config validator and has no IAM permission; it is never queried. Run Command runs with administrative OS impact on this disposable host. IAM cannot constrain the content of a document the operator is allowed to create/delete; it could technically replace its own document with other commands. Packet hash/native document review and the one-command ledger are execution constraints, not an IAM guarantee of read-only commands. The custom document has a fixed literal status command, Action allowedValues=[status], no arbitrary shell interpolation. A successful command proves only this new status harness.

The sanitized capture omitted raw lines, and absence of the command ID does not prove non-delivery to the agent. The exact asynchronous denial remains unresolved. No new IAM change or cycle is authorized by this correction.

Current `evidence_export.py` accepts an already authorized `filter_log_events` callable; it constructs no AWS client and makes no call on import. Use `export_boot_events(logs_client.filter_log_events, config, instance_id)` instead of a single page. It validates scope and every record, follows even empty pages with a new token, deduplicates identical event IDs, rejects conflicting IDs, and never retries a failed request. The complete serialized export stays within 120 events and 2 MiB, including its envelope. A separate 128-page ceiling prevents an endless stream of empty pages. `Capture.PaginationExhausted` is true only at the end of pagination; `StopReason` distinguishes event/byte/page limits, a repeated token and a fetch failure. `TruncatedByApi` remains a conservative legacy alias for incomplete capture, including local bounds, not proof of server truncation. Even exhausted pagination describes that read, not a delivery guarantee or a snapshot of concurrently arriving logs.

Actions and codes still use closed enums; arbitrary strings, unlabelled UUIDs, raw lines and secrets are omitted. Adjacent rows are never silently merged into a claimed error/command association.
